Airmux RS v0.4.2 — SSH 下载代理 / SSH download proxies

### 更新内容

- 管理员可在「设置 / 系统设置」统一维护 SSH 下载代理，支持密码或未加口令的私钥认证。订阅源、规则集同步及服务端 URL 规则预览可下拉选择代理或直连，复用现有下载与交互组件。
- 配置列表及新增、编辑弹窗提供「测试连接」，显示耗时或认证、公钥、DNS、网络失败原因；测试表单不会保存配置，执行期间防止重复操作。
- 密码认证无需手动填写 known_hosts，首次连接自动记录主机公钥，后续连接校验；已有公钥记录保留严格校验。私钥认证继续要求已核对的主机公钥。
- 密码和私钥加密保存且不回显。停用或连接失败不会回退直连；引用中的配置不能删除。订阅源切换连接方式保留原 UA 和请求头。
- 同步诊断补充所选 SSH 配置、修订、主机和端口、建连耗时与失败阶段，日志不包含认证凭证、主机公钥或原始 SSH 输出。

### 升级说明

镜像架构为 `linux/amd64`，最低支持当前版本 `0.1.2`。追加 `0032_ssh_profiles.sql`，共 32 个迁移；已发布的前 31 个迁移保持不变。保留原数据库、管理员及 `config.yaml` 中的加密密钥。

推荐通过系统版本菜单检查、准备并重启升级。手动升级使用 `AIRMUX_VERSION=v0.4.2`；已设置 `AIRMUX_APP_IMAGE` 时，替换为附件 `release-manifest.json` 的实际 `image` 值。

现有部署启用密码 SSH 代理前，请对照 public 新版 `compose.yaml` 或 `compose.external.yaml`，在 API 挂载 `ssh-host-keys:/var/lib/airmux-ssh`，并在顶层 `volumes` 声明 `ssh-host-keys`，然后重新创建 API。保留自己的目录、端口、数据库和其他自定义挂载。系统升级器保留原 Compose 文件；补充此卷后，自动记录的公钥可在容器重建后保留。新安装的分发文件已包含该卷。

SSH 代理用于服务器下载，不改变客户端的下载出站。SSH 主机和下载目标继续使用现有地址白名单及 TLS 校验；需要访问内部 SSH 主机时，在服务器 `fetch.allowlist` 配置精确的主机、端口和 IP。

### Changes

- Administrators can manage shared SSH download profiles in System Settings, with password or unencrypted private-key authentication. Subscription sources, rule synchronization and server-side URL rule previews select a profile or direct access.
- Add connection tests to profile rows and create/edit dialogs, reporting elapsed time or authentication, host-key, DNS and network failures. Testing does not save profile settings and prevents duplicate operations.
- Password authentication needs no manual known_hosts entry. The server records the first observed host key and checks it on subsequent connections. Existing pins remain strict; private-key authentication still requires verified host keys.
- Encrypt credentials without reading them back. Disabled profiles and failed connections never fall back to direct access. Protect referenced profiles from deletion and preserve source headers and user agents when changing transports.
- Extend synchronization diagnostics with safe SSH profile context and connection timing, excluding credentials, host keys and raw SSH output.

This release targets `linux/amd64`, requires a current version of at least `0.1.2`, and adds migration `0032_ssh_profiles.sql` for a total of 32. Preserve your database, administrator and encryption key. Use the version menu, or select `v0.4.2` and update a pinned image from the attached manifest.

Before enabling password SSH proxies on an existing deployment, add `ssh-host-keys:/var/lib/airmux-ssh` to the API volumes and declare `ssh-host-keys` under top-level volumes, following the new public Compose file. Recreate the API while retaining local deployment settings. The updater preserves your Compose file; the added volume retains automatic host-key records across container recreation. New installations already include it.
