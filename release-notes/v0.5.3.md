# Airmux RS v0.5.3

本次优化公共方案大配置的保存过程，编辑器按业务分区提交，减少整份配置反复上传、解析和数据库写入。

## 公共方案分步保存

- 基本信息、节点、地区、分组、规则集、规则路由与 DNS 解析地址分别保存，其他分区未保存的草稿继续保留。
- 规则目录先读取元数据，打开单条规则时再加载原文。规则逐条保存，后续失败时保留前面已成功的步骤，可继续保存剩余修改。
- 新建方案先取得稳定标识，首次请求超时后重试不会重复创建。默认测速和最终兜底尚未明确时，方案标记为配置未完成，不能供客户端引用或生成。
- 地区定义与分组行为分别保存。删除地区会原子清理对应组成员和人工地区覆盖；仍有路由、兜底或客户端引用对应组时，删除会被阻止。
- 数据库只更新当前分区，关系批量写入。修改名称或 DNS 不重写已有规则正文，同一账号写入锁等待超过五秒时返回可重试提示。

## 安装与升级

- 正式镜像为 `docker.io/jaelinker/airmux:v0.5.3`，支持 `linux/amd64`，发行附件清单提供固定摘要。
- 最低可升级版本仍为 **0.5.0**，数据库代际为 `plan-local-v1`；旧 `0.4.x` 需要独立空库安装。
- 仅追加 `0012_common_plan_sections.sql`，十一份已发布迁移保持不变。既有完整方案升级后保持可用，原有方案版本和规则正文不变。
- 升级保留原数据库、程序加密主密钥、SSH 主机记录和更新器状态。通过系统更新入口准备镜像，在维护时间重启；失败后保留备份与状态，按部署指南恢复，不删除迁移历史。

## 验证范围

Rust 工作区 108 项、隔离 PostgreSQL 数据库 38 项、前端 233 项和 Python 55 项回归通过，接口类型生成、类型检查、生产构建与原型构建通过。覆盖六十万字节规则原文、一千条路由批量保存、密文保留、稳定创建重试、锁等待上限、版本冲突、所有者隔离和跨分区草稿。

正式候选镜像已通过三文件模板空库安装、十二条迁移、默认地区、首次改密、静态资源和大规则分步保存验收。使用正式 0.5.2 镜像与合成数据完成真实更新器升级，十一条迁移增至十二条，既有方案保持完整可用，版本与规则密文不变，十四张核心表业务指纹一致。独立故障库通过同名字段冲突触发迁移失败，确认进入 `needs_recovery` 并停止 API；成功与失败流程的真实备份均恢复到独立库，十四张核心表指纹一致，并使用旧 0.5.2 镜像恢复就绪。

Mihomo v1.19.33 的四个固定参考用例通过原生检查，无效配置按预期拒绝。本轮未执行浏览器实屏验收或线上请求耗时验证，线上 524 的改善需部署后观察；Loon 按既有要求继续暂缓验证。未操作用户部署或业务数据库。
