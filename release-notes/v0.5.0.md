# Airmux RS v0.5.0

本次以全新结构重构订阅聚合、节点、两层方案与访问链接，并统一界面、配置归属和 Docker Compose 更新链路。

## 安装边界

- 镜像仓库为 `docker.io/jaelinker/airmux`，标签 `v0.5.0`，平台 `linux/amd64`。应用版本为 `0.5.0`。
- **新数据库代际**：旧 `0.4.x` 数据库不支持直接升级，请独立空库安装并保留原库及加密密钥。此后的正常版本追加 SQL，保留已有数据。
- 公共仓库提供三文件安装模板与固定摘要清单，程序启动参数在 `config.yaml`，Docker 发布参数在 Compose 和 `.env`，动态管理设置在数据库。

## 主要功能

- URL、文件与手动节点统一入口，支持六类节点协议、别名身份、整批导入、完整原始参数保留及逐客户端兼容诊断。URL 支持 UA、请求头与 SSH 隧道获取。
- 公共方案维护节点、方案地区、规则集、分组、路由及 DNS 地址目录。客户端方案独立配置本类型 DNS、域名、运行与网络能力，不重复维护地址。
- 远程规则使用原始 URL 并提供客户端更新参数，不导出管理员凭据；手动规则直接生成。无法保留含义时阻断对应客户端并说明原因。
- 私有访问链接支持重复复制、短时缓存、并发合并、强制刷新、禁用与轮换，生成内容可预览和下载。
- 邀请邮件提供账号、临时密码与确认链接，确认页展示账号；临时密码或链接共用一次机会，首次改密免当前密码。删除账号同步清理所属资源。
- 固定侧栏与图标工具栏、主题切换、抽屉层级、通知、提示、拖动排序和可配置表格列宽统一采用确认原型。
- 更新入口集中在品牌版本徽标，准备镜像后等待维护重启，执行备份、迁移与健康检查；失败停止 API 并保留人工恢复资料。

## 验证范围

已运行 Rust 工作区回归、34 项隔离 PostgreSQL 集成测试、224 项前端测试、类型检查、生产与原型构建、55 项 Python 发行及更新器测试。现有方案通过 Mihomo v1.19.33 原生配置检查。

本地 Docker 使用实际镜像完成准备、停机、有效备份、迁移入口和健康恢复；另外通过故意失败的迁移验证 needs_recovery 及独立库人工恢复。十二张核心表的稳定数据指纹保持一致。演练版本使用同一新基线九份 SQL，没有新增业务迁移；不代表支持旧模型自动转换。

Loon 验证按本轮要求暂缓，未声称实机通过。真实 SMTP 投递和 SSH 服务器连接未在本次部署验收中执行，应在实际部署环境验证。

## 更新与恢复

下载并更新无需二次确认，只准备镜像；立即重启需要确认维护窗口。更新失败不能仅回退镜像或删除迁移历史，应保留原密钥、旧镜像、持久化状态和有效备份，恢复到独立空库并核对数据。详见公共仓库部署说明。
