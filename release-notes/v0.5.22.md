# Air.mux v0.5.22

修复新增规则及路由时，未修改的已有规则被误报缺少正文的问题。

## 本次改动

- 修复已有手动规则按需查看后，正文比较基线与管理抽屉草稿不同步的问题。“未读取正文”的状态不再被误认为“清空正文”，新增其他规则或路由不需要重新保存旧规则。
- 正文读取只更新比较缓存，不修改未应用的编辑草稿；再次查看可复用缓存。只看不改、取消单项编辑或应用未修改列表均不触发多余保存。
- 真正修改正文、新增规则、修改规则行为或格式、更新远程地址仍按原流程提交。未改正文保留服务器原文及密文，大正文不会因只读查看而被重新上传。
- 保留后端对缺失手动正文、无效定义、版本冲突及关联方案的检查，不用跳过校验掩盖错误。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.22`，平台 `linux/amd64`，固定摘要和源码提交见发行附件。
- 无新增 SQL，沿用十四份不可变迁移。从 `0.5.21` 升级保留节点、配置、方案、规则正文、访问链接和引导状态。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前升级仍会执行清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料与系统配置保留。升级前备份数据库并保管原加密主密钥；旧 `0.4.x` 须独立空库安装。
- 保留详细更新与停服只读观察能力。从更早版本首次启用时仍须按部署指南配套更新 API、前端和更新器；应用在线更新不会自行重建 updater。

## 验证范围

- 新增九项前端回归覆盖未查看与查看后取消、增加规则和路由、只看不改、大正文不回传、真实正文修改、仅修改说明、远程地址变化及取消编辑后缓存复用。修复前可复现的三项误提交现均通过。
- Rust 工作区回归、四十三项隔离 PostgreSQL 集成回归、三百六十八项前端及六十五项 Python 测试通过，格式、类型检查、正式与原型构建通过。
- 新增隔离 PostgreSQL 真实预检及保存回归，确认仅提交新规则和路由时，旧规则正文与原密文逐字节保持。
- Loon 原生、实机及真实代理流量继续暂缓。生产环境与外部 SMTP、SSH 实服未在本轮重验。

- 最终镜像真实浏览器完成查看旧规则后取消、新增规则及路由、保存的完整复现。预检和保存请求均只携带新规则，旧规则未作为正文变更提交；保存成功后核对旧原文及密文均保持不变，并实际生成配置。
- 最终镜像通过三文件空库安装、默认七地区、首次管理员改密、版本与源码标签检查，以及既有共享合并和规则诊断回归。
- 从正式 0.5.21 正常升级及迁移退出码 42 故障演练通过，33 张业务表完整字段摘要与迁移历史保持；两份自动备份使用原密钥恢复到独立库并实际读取和生成，十六份产物通过固定摘要的 Mihomo 原生检查。
