Airmux RS v0.4.1 — 规则集同步诊断 / Rule-set synchronization diagnostics

### 更新内容

- 管理员规则集列表新增「同步日志」，在弹窗中查看最近 30 条任务；先展示失败阶段和底层错误，再展示提交、开始、结束时间与同步上下文，支持复制完整诊断。
- 记录下载时的 DNS 与实际选择的 IP、重定向、HTTP 状态、耗时、连接/总超时、文件大小与生效上限；保留源站提供的请求 ID、CF-Ray 和 Retry-After，帮助区分连接中断、限流、超时和文件过大。
- 记录任务配置快照、触发来源、此前失败次数和 worker 版本/实例；服务器同步日志通过任务 ID、规则集 ID 关联。内容校验错误继续显示真实源文件行列，失败保留当前有效内容。
- 诊断仅管理员可查看，URL 与错误链脱敏，不保存 Cookie、完整请求头、响应正文或历史规则文件。旧任务保留原状态，重新同步后生成详细诊断。

### 升级说明

镜像架构为 `linux/amd64`，最低支持当前版本 `0.1.2`。追加 `0031_rule_set_sync_diagnostics.sql`，共 31 个迁移；已发布的前 30 个迁移保持不变。升级前备份数据库，保留现有数据库、`config.yaml` 和加密密钥，无需重新初始化管理员。

推荐通过系统版本菜单检查、准备并重启升级。手动升级使用 `AIRMUX_VERSION=v0.4.1`，同时更新 api、frontend、updater；若 `AIRMUX_APP_IMAGE` 已固定摘要，应替换为附件 `release-manifest.json` 中的实际 `image` 值。

此次增强诊断，没有调整下载上限、同步频率、退避、重试、代理或 IP 选择策略。默认下载上限仍为 2 MiB，由 `fetch.max_bytes` 控制；生产升级后再次同步，才能获取新诊断并判断具体网络原因。

### Changes

- Add an administrator-only synchronization log dialog with the latest 30 jobs per rule set. Show the failure stage and underlying causes first, followed by timestamps and context; complete diagnostics can be copied.
- Record DNS results, the selected IP, redirects, HTTP status, timings, effective connection/total timeouts, file size and limit, and available origin request IDs, CF-Ray and Retry-After.
- Capture the submitted configuration, trigger, prior failure count and worker version/instance. Server logs correlate by job and rule-set IDs. Content validation retains actual source line/column positions, and failed synchronization preserves effective content.
- Redact URLs and error chains. Diagnostics exclude cookies, complete request headers, response bodies and historical rule files. Existing jobs retain their original status; new synchronizations produce detailed diagnostics.

This release targets `linux/amd64` and requires a current version of at least `0.1.2`. It adds `0031_rule_set_sync_diagnostics.sql`, bringing the migration total to 31; the first 30 published migrations are unchanged. Back up the database and preserve `config.yaml` and the encryption key. Use the version menu, or set `AIRMUX_VERSION=v0.4.1` and update api, frontend and updater together. Replace a pinned `AIRMUX_APP_IMAGE` with the attached manifest's `image` value.

Download limits, synchronization schedules, backoff, retries, proxy behavior and IP selection remain unchanged. The default download limit is still 2 MiB, configurable through `fetch.max_bytes`. Synchronize again after upgrading to collect the new diagnostics.
