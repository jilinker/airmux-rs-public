# Air.mux v0.5.20

添加共享功能配置时，同名冲突可以逐项对比和选择补充；内容一致直接跳过。

## 本次改动

- 配置库找到本人同名、同客户端的功能配置后，展示两边差异，按项选择采用共享内容。共享新增项可批量选择，未选内容及本人独有内容保留。
- 内容相同直接提示跳过，不创建重复副本。批量导入逐份处理，成功与跳过项退出选择，未完成项保留重试。
- 规则正文按需查看，合并时由服务器复制，保留已有规则与路由身份、相对顺序和未改正文密文。引用缺失时明确提示所需项目，未公开材料不能覆盖本人绑定。
- 预检和保存均检查共享权限、双方版本与实际内容摘要。涉及关联方案时沿用影响确认流程，配置、节点、规则与方案统一提交，取消或失败不写入。
- 修正自动或明确复用节点后的包内入站引用，并避免节点别名与原名包含分隔符时误判为同一身份。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.20`，平台 `linux/amd64`，固定摘要和源码提交见发行附件。
- 无新增 SQL，沿用十四份不可变迁移。从 `0.5.19` 升级保留现有节点、配置、方案、访问链接和引导状态。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前升级仍会执行清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料与系统配置保留。升级前备份数据库并保管原加密主密钥；旧 `0.4.x` 须独立空库安装。
- 本次逐项合并用于功能配置，基础配置保留原导入流程。未公开材料及共享包之外的失效引用仍需在所属配置中处理。
- 保留详细更新与停服只读观察能力。从更早版本首次启用时仍须按部署指南配套更新 API、前端和更新器；应用在线更新不会自行重建 updater。

## 验证范围

- Rust 工作区回归、十项合并业务回归、四十一项隔离 PostgreSQL 集成测试及三百四十六项前端测试通过，格式、类型检查、正式和原型构建通过。
- 真实 HTTP 往返覆盖鉴权、比较、准备候选、影响检查及保存；隔离数据库覆盖选择、正文复制、身份与密文保留、方案失败回滚、所有权与共享权限检查、节点复用后的入站引用。
- 浏览器通过合成接口检查实际业务组件的逐项选择、依赖提示、按需正文、核对、取消和一致跳过，检查桌面、窄窗口及深色布局。
- 隔离合并后实际生成的 Mihomo 配置通过 Meta v1.19.33 原生检查。Loon 原生、实机及真实代理流量继续暂缓，生产网络端到端及外部 SMTP、SSH 实服未在本轮重验。

- 最终镜像通过三文件空库安装、默认七地区、首次管理员改密、真实 HTTP 版本与源码检查。真实双账号验证规则逐项合并、按需正文、原身份保留、关联方案未确认拒绝提交及保存后再次比较一致。
- 从正式 0.5.19 正常升级与迁移退出码 42 故障演练通过，33 张业务表完整字段摘要及迁移历史保持，两份自动备份以原密钥恢复到独立库并实际读取和生成。十四份真实生成产物通过固定摘要的 Mihomo 原生检查。
- 最终镜像真实浏览器验证内容一致跳过，以及差异对照、勾选、核对、保存后列表更新。升级与故障停服期间的只读观察持续可用。
