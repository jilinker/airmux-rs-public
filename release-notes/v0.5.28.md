# Air.mux v0.5.28

修复功能配置使用基础配置中的 DNS 地址后，更换基础配置时报「解析地址必须来自当前公共方案」的问题。

- 保存功能配置时，将实际引用的 DNS 地址复制为独立副本，保留策略、解析器用途及方案启停选择。未使用的地址不复制，同名同内容可复用本功能地址。
- 已有数据通过新增的第十五份迁移一次性修复。解密、SQL 转换、加密回写和迁移成功记录原子提交，正常读取与生成不保留旧引用兼容逻辑。
- 只从同一用户、同一客户端的基础配置查找原地址。来源缺失、内容歧义或同名冲突会阻止升级并回滚；错误会给出配置及地址标识。复制新增私人 DNS 地址时，需要重新确认敏感内容公开许可。

## 升级说明

升级会执行 `0015_feature_dns_local.sql`，必须保留当前部署的原加密主密钥，并通过新版本原生迁移入口执行。升级前请备份数据库；遇到未解决的引用问题，应先核对原配置，不要删除迁移历史或直接改写密文。

最低升级版本为 0.5.0。**从 0.5.9 之前升级会执行历史清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接。** 0.4.x 须独立空库安装。Loon 本轮仅验证地址数组的数据迁移，原生与实机验收继续暂缓。
