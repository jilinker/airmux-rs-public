Airmux RS v0.4.4 — 完整保留节点参数 / Preserve node parameters

### 更新内容

- 原生 Mihomo YAML 订阅节点完整保留所有字段和值，包括 `udp`、`packet-encoding`、Reality、`region` 和未知嵌套扩展参数。生成方案时仅按已有命名规则调整节点名称。
- 导入快照记录输入格式，避免把原生 YAML 中名为 `uri` 或 `add` 的扩展字段误识别为链接配置。旧快照通过保留的原始订阅识别格式，无需重新导入。
- URI／旧 VMess 链接转换保留未知扩展参数，并正确保留显式配置的 UDP 开关和数据包编码。`udp: false` 保持关闭，未配置 UDP 时沿用客户端默认行为。

### 升级说明

本版本无需新增数据库迁移，保留现有 32 个迁移、数据库、账号、SSH 配置及加密密钥。

已发布方案的下载文件是不可变产物，升级系统不会改写历史文件。升级后使用当前订阅节点重新生成预览并发布新的方案版本，再更新客户端订阅；固定到旧方案版本的访问链接需切换版本或改为跟随最新版。

### Changes

- Preserve every native Mihomo YAML node field and value, including UDP, packet encoding, Reality, region and unknown nested extensions. Only apply the existing node naming rules during generation.
- Record the subscription input format to distinguish native extensions named `uri` or `add` from link configuration. Resolve legacy snapshot formats from retained source content without requiring reimport.
- Keep unknown extensions during URI and legacy VMess conversion. Preserve explicit UDP settings and packet encoding; retain false values and leave omitted UDP settings unspecified.

No new database migration is required. Keep all 32 existing migrations, your database, accounts, SSH profiles and encryption key.

Published plan artifacts remain immutable. After upgrading, preview and publish a new plan version, then refresh the client subscription. Links pinned to an old plan version must select the new version or follow the latest release.
