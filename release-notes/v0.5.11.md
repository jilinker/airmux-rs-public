# Airmux RS v0.5.11

方案功能配置支持抽屉批量加入，路由与 DNS 分区改为独立抽屉，配置名称与说明分行展示。

## 方案编辑

- 添加功能配置从右侧抽屉跨页勾选后统一加入，支持全选当前页与清空选择。搜索、翻页和刷新保留选择，已经加入的配置不会重复加入或重置节点选择。
- 所选配置一起读取并预检，任一读取失败保留原方案及抽屉选择。加入只更新方案草稿，保存方案后生效。
- 配置冲突、路由顺序、DNS 策略顺序和 Fake IP 条目顺序分别使用独立抽屉。取消不改变方案，应用只更新当前分区；其他顺序和节点设置保持。
- 配置选择表格的名称与用途上下两行展示，桌面和窄视口均保留完整内容及底部操作。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.11`，平台 `linux/amd64`。固定摘要和实际源码提交见发行附件。
- 无新增 SQL，沿用十三份不可变迁移和数据库代际 `plan-local-v1`。从 `0.5.9` 或 `0.5.10` 升级保留现有配置、方案及访问链接。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前的版本升级仍会执行 `0.5.9` 引入的清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料及系统配置保留。升级前备份数据库并保管原加密主密钥，旧 `0.4.x` 仍须独立空库安装。

## 验证范围

- Rust 工作区 125 项、PostgreSQL 显式随机隔离库 35 项、前端 291 项和 Python 55 项回归通过；格式、契约生成、类型检查、生产与原型构建通过。
- 正式页面验证批量加入、名称说明分行、桌面及 640px 视口，以及各排序抽屉的取消隔离和独立应用。未保存的操作不改变数据库中的方案。
- 最终镜像通过三文件空库安装，默认地区、首次强制改密、版本来源和真实 HTTP 保存重读生成均通过，实际生成内容通过 Mihomo v1.19.33 原生配置检查。
- 从正式 0.5.10 完成正常升级及故障停机演练，33 张业务表指纹和十三份迁移保持一致。两份备份分别恢复到独立库，使用原密钥及旧版镜像就绪，真实 HTTP 读取 35 个节点及方案并生成配置通过。
- Loon 本轮继续暂缓原生与实机验证，未做真实代理流量验证。
