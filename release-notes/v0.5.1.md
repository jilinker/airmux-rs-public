# Airmux RS v0.5.1

本次完善 SSH 默认身份和主机公钥管理，并验证从 0.5.0 到 0.5.1 的真实 SQL 升级与人工恢复。

## SSH 改进

- 密钥认证允许私钥留空，使用 API 运行用户的默认 SSH 身份文件或 SSH agent；密码认证仍需提供密码。
- 主机指纹和 known_hosts 记录可选。默认复用运行环境记录，首次公钥写入持久化文件，后续公钥变化仍拒绝连接。
- 支持仅填写指纹锁定主机，也可继续提供显式公钥记录进行严格校验。
- 编辑时不填写私钥或主机记录会保留已有值；使用默认密钥、使用默认记录操作可明确清空覆盖值，保存后生效。
- Docker 不会自动读取宿主机密钥。需要时给 API 显式只读挂载身份文件，或挂载 agent 套接字并设置 SSH_AUTH_SOCK。默认 Compose 保留主机公钥持久化卷。

## 安装与升级

- 镜像为 `docker.io/jaelinker/airmux:v0.5.1`，同时提供 `0.5.1` 和 `latest`，平台为 `linux/amd64`。固定摘要见发行附件 `release-manifest.json`。
- **最低可升级版本为 0.5.0**，数据库代际保持 `plan-local-v1`。保留原数据库、加密主密钥、SSH 主机记录卷及更新器状态，按系统更新流程准备镜像后选择维护时间重启。
- 仅追加 `0010_optional_ssh_host_key.sql`，放宽 SSH 指纹非空约束并提供空默认值，不改写前九份 SQL，不重置已有凭据、指纹或业务数据。
- 旧 `0.4.x` 模型仍不能直接升级，需独立空库安装；本次没有增加旧模型接入层。

## 验证范围

Rust 工作区 106 项、隔离 PostgreSQL 35 项、前端 226 项及 Python 55 项回归通过，类型检查与生产构建通过。正式镜像通过三文件模板独立空库安装、十份 SQL 摘要校验、七条默认地区、首次改密、模块接口及更新器版本检查。

真实 OpenSSH 临时服务验证了显式私钥、密码、默认 agent、容器默认身份文件、正确与错误指纹以及公钥变化拒绝行为。Chrome 管理页可选字段留空测试通过。用户已确认 SMTP 实际投递成功；外部 SSH 服务器的账号、权限、网络和转发能力仍需按实际部署确认。

更新器已在隔离数据副本完成正式 0.5.0 九条迁移到本地 0.5.1 十条迁移，十四张核心表的数据指纹一致。另一个副本通过 schema 漂移触发真实 SQL 失败，进入 `needs_recovery` 并停止 API；成功和失败备份均已恢复到独立库并验证旧版就绪。用户业务数据库未参与测试写入。

Mihomo v1.19.33 四项参考配置原生检查符合预期，包含无效配置拒绝；实际方案的既有原生检查记录保留。Loon 按用户要求继续暂缓验收。

更新失败保留备份、原密钥、原镜像和状态，按部署指南恢复到独立空库并核对数据，不通过删除迁移历史或仅降级镜像绕过恢复。
