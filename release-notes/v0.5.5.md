# Airmux RS v0.5.5

公共方案支持有大小和时长限制的批量保存；规则导入由后端按来源 ID 复制，避免大正文在浏览器往返，手动正文严格限制为 1 MiB。

## 有界批量保存

- 新增 `PUT /api/v1/common-plans/{id}/sections/batch`，请求使用当前正 `revision` 和有序 `changes`，响应沿用轻量保存回执。
- 每批一至二十项，完整 UTF8 JSON 最多 **1 MiB**，同一分区或规则不允许重复。每批只读取和校验一次方案结构，批量写入变化关系与规则，原子提交且版本只递增一次。
- 前端以 **512 KiB** 为目标并按二十项上限拆批，计入中文及 JSON 转义后的字节。已成功批次保留，后续失败只重试未保存改动，其他分区草稿不清空。
- 合法手动正文超过批量目标时独立提交，不拆成不完整正文。新建方案先单独保存基本信息，保留稳定标识的创建重试机制。
- 导入规则只提交基础 **ID 和版本**，后端读取成功内容并复制为独立加密副本，预览和回执不携带大正文或管理员获取凭据。手动新增或修改正文严格限制为 **1 MiB（UTF-8 字节）**，基础规则、分区及兼容整份接口均校验。远程单条成功内容及单批后端复制总量最多 **20 MiB**，前后端共同限制并拆批；名称 说明和远程周期单独保存，保留原正文密文。
- 单分区与批量保存从规则解析至事务提交的处理预算为 **20 秒**，所有者锁等待及单条 SQL 最多 **5 秒**。处理超时保留草稿并提示重新读取核对结果，不自动重发。
- 未涉及的分区和规则密文保持原值，所有者隔离、并发版本和客户端引用保护继续生效。OpenAPI、前端生成类型和项目规范已同步。

## 安装与升级

- 镜像为 `docker.io/jaelinker/airmux:v0.5.5`，支持 `linux/amd64`，清单提供固定摘要和实际源码提交。
- 最低可升级版本为 **0.5.0**，数据库代际为 `plan-local-v1`；旧 `0.4.x` 需要独立空库安装。
- 本版没有新增迁移，十二份已发布 SQL 摘要保持不变。升级保留原程序加密主密钥、数据库、SSH 主机记录及更新器状态。
- 失败后按部署指南保留备份和现场，不删除迁移历史或直接降级已有数据库。
