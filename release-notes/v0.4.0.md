Airmux RS v0.4.0 — 规则集库与可搜索下拉 / Rule-set library and searchable selectors

### 更新内容

- 新增管理员规则集库：每条外部 URL 同步一个规则文件，可手动同步或配置自动同步周期；也可在系统内维护 YAML/text。外部 MRS 支持二进制结构校验，失败保留当前有效内容。
- 方案与模板可下拉选用库规则集，也保留原 URL 模式。规则集不进入历史版本管理；客户端按原有 `interval` 获取最新有效文件，保留 provider ID、路由/DNS 引用及下载出站。
- 正式页面所有下拉统一支持菜单顶部搜索，规则集库外置搜索已合并；筛选不改变当前值，选择结果后按规则集 ID 联动行为和格式。
- 删除确认优先于右上角通知，确认不自动关闭；通知继续使用 5 秒进度条。规则集内容在弹窗中显示行号，方案与模板的删除入口统一位于右上角。
- 修复取消节点使用后误报节点失效。预览展示具体异常项和恢复入口；规则文件校验显示真实行列，下载和网关异常保留实际 HTTP 状态与可用排查编号。

### 升级说明

镜像架构为 `linux/amd64`，最低支持当前版本 `0.1.2`。新增 `0029_rule_sets.sql`、`0030_rule_set_sync_policy.sql`，全部 30 个迁移随镜像提供。升级前备份数据库，保留现有数据库、`config.yaml` 与加密密钥，无需重新初始化管理员。

生产使用规则集库时，必须配置 `server.public_base_url` 为客户端可访问的 HTTP(S) origin，例如 `https://airmux.example.com`；不带路径、查询参数或账号信息，并确保反向代理转发 `/sub/`。已有部署需在原配置中补充此项，修改后重新创建 API 容器；未配置时不能发布使用库规则的方案。

推荐通过系统版本菜单检查、准备并重启升级。手动升级使用 `AIRMUX_VERSION=v0.4.0`，同时更新 api、frontend、updater；若 `AIRMUX_APP_IMAGE` 已固定摘要，应替换为本 Release 附件 `release-manifest.json` 中的实际 `image` 值。

### Changes

- Add an administrator-managed rule-set library. Each external URL synchronizes one file manually or on a configurable schedule; YAML/text can also be maintained in the system. External MRS files receive binary structure validation, and failed synchronization preserves effective content.
- Select library rule sets in plans and templates while retaining direct URL mode. Rule sets have no version history; clients fetch the latest effective content using their existing `interval`. Provider IDs, routing/DNS references, and download outbounds are preserved.
- All production selectors support search at the top of their menus. Library search is integrated into the selector; filtering leaves the current value unchanged, and selecting a result updates behavior and format through its rule-set ID.
- Deletion confirmations take priority over top-right notifications and never close automatically. Notifications retain the five-second countdown. Rule-set content opens in a line-numbered dialog, and delete actions share the top-right position in plans and templates.
- Fix invalid-node reports after excluding nodes. Previews identify affected items and recovery actions; rule-file validation reports real line and column positions, and download or gateway failures retain actual HTTP status and available diagnostic IDs.

This release targets `linux/amd64` and requires a current version of at least `0.1.2`. It adds `0029_rule_sets.sql` and `0030_rule_set_sync_policy.sql`, bringing the migration total to 30. Back up the database and preserve `config.yaml` and the encryption key; administrator reinitialization is unnecessary.

For production library use, set `server.public_base_url` to a client-reachable HTTP(S) origin without a path, query, or credentials, and forward `/sub/` through the reverse proxy. Add this setting to existing configurations and recreate the API container after editing; publishing plans with library rule sets requires it. Use the version menu, or set `AIRMUX_VERSION=v0.4.0` and update api, frontend, and updater together. Replace a pinned `AIRMUX_APP_IMAGE` with the actual `image` value from the attached `release-manifest.json`.
