# Air.mux v0.5.19

列表读取减少数据库往返，页面先显示结构与分页加载状态，节点翻页只查询当前页。

## 本次改动

- 共享分页由五次数据库交互合并为单条 SQL，总数、页码校正和记录保持同一快照。节点、方案、配置库、共享发现、链接、规则及用户目录在没有搜索词时跳过文本计算。
- 节点列表独立于来源、编辑选项和手动数量呈现；翻页及筛选只请求当前页，显式刷新或业务变更后再更新辅助信息，不触发订阅获取。
- 页面先显示页头、筛选、表头和分页栏。首次查询显示骨架，分页显示正在读取；再次查询保留已有记录、列宽及选择，完成后再显示真实范围或空结果，减少动效偏好使用静态占位。
- 启动时立即显示会话恢复反馈，认证完成后再进入个人页面，并发导航复用同一次会话查询。修正节点页窄窗口的筛选和操作区溢出。
- 性能测量、独立请求、加载与失败行为及验收边界写入开发规范和发行检查。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.19`，平台 `linux/amd64`，固定摘要和源码提交见发行附件。
- 无新增 SQL，沿用十四份不可变迁移。从 `0.5.18` 升级保留现有节点、配置、方案、访问链接和引导状态。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前升级仍会执行清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料与系统配置保留。升级前备份数据库并保管原加密主密钥；旧 `0.4.x` 须独立空库安装。
- 保留 `0.5.18` 的详细更新与停服只读观察。首次从更早版本启用该能力仍须按部署指南配套更新 API、前端及更新器；应用在线更新不会自行重建 updater。

## 性能测量边界

本机 PostgreSQL 17 的两万条合成记录中，每页三十条读取第二页且没有搜索词，前后交替执行，各预热二十次并采样一百次。分页查询中位耗时从 4.476 毫秒降至 1.990 毫秒，P95 从 4.959 毫秒降至 2.379 毫秒。

这些数字仅表示隔离数据库查询，不包含生产网络、认证、节点解密、接口序列化和浏览器耗时，不作为线上固定延迟保证。

## 验证范围

- Rust 工作区回归、隔离 PostgreSQL 三十八项、前端三百三十九项通过；格式、类型检查、正式及组件原型构建通过。
- 延迟合成接口检查 1366px 与 640px、浅色与深色加载状态，覆盖首次加载、分页等待、辅助请求不阻塞列表和失败保留内容。
- 最终镜像三文件空库安装、默认七个地区、首次管理员改密、实际保存重读及生成通过，真实 HTTP 版本和源码提交与镜像标签一致，十四份 SQL 摘要保持不变。
- 从正式 0.5.18 正常升级及迁移退出码 42 故障演练通过，33 张业务表完整字段摘要及迁移历史保持；两份自动备份均保留原密钥恢复到独立库，恢复后实际读取并生成配置。十二份真实生成产物通过固定摘要的 Mihomo 原生检查。
- 最终镜像的真实浏览器验证等待首屏查询时仍显示筛选、五列表头与五行骨架；节点翻页仅发出一个当前页请求，等待时保留三十行原记录，完成后正确呈现五条记录及 31–35 的范围。正常升级与故障停服期间，只读通道均能读取结果。
- Loon 原生、实机及真实代理流量继续暂缓。线上端到端延迟及外部 SMTP、SSH 实服未在本轮重验。
