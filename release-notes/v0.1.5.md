Airmux RS v0.1.5 — 规则集展示排序与升级诊断 / Rule-set display sorting and upgrade diagnostics

### 更新内容

- 方案模板和配置方案的“路由与 DNS → 规则集”支持拖动排序，沿用现有排序手柄，也可使用键盘上下方向键移动。
- 展示顺序随模板保存或方案自动保存保留，拖动时保留规则集的展开与编辑状态。
- 排序仅用于页面归类查看，不改变路由规则、DNS 策略的匹配顺序或已有规则集引用；已验证排序前后的生成 YAML 完全一致。
- 改进升级前的版本检测错误提示，明确指出部署目录挂载、`.env`、Compose 项目或镜像版本标签的问题，便于排查“无法确认当前版本”。
- 保留升级安全检查：无法可靠识别当前运行版本时仍拒绝升级，并避免在错误提示中泄露配置凭据。

### 升级说明

镜像架构为 `linux/amd64`，本版本没有新增数据库迁移。保留已有数据库、`config.yaml` 和加密密钥，无需重新初始化管理员账号。

可通过系统版本菜单执行在线更新。手动升级时，将 `.env` 中的 `AIRMUX_VERSION` 改为 `v0.1.5`，然后执行：

```sh
docker compose pull api frontend updater
docker compose up -d --wait
docker compose ps
```

如果 `AIRMUX_APP_IMAGE` 已被在线更新设置为固定摘要，手动升级时还需将其替换为本 Release 附件 `release-manifest.json` 中的 `image`。该覆盖值优先于 `AIRMUX_VERSION`。

升级诊断由 updater 提供，手动升级需同时更新并重建 updater。`config.yaml` 的 `deployment.directory`、`.env` 的 `AIRMUX_DEPLOY_DIR` 和服务器实际部署目录应一致，目录中需存在 `config.yaml`、`compose.yaml` 和 `.env`。

### Changes

- Added drag sorting to rule-set lists in plan templates and plans, with the existing drag handle and Up/Down keyboard support.
- The display order persists through template saves or plan autosave. Expanded and editing states are preserved.
- Sorting organizes the editor only. Route priority, DNS policy priority, provider references, and generated YAML remain unchanged.
- Upgrade preflight now provides actionable diagnostics for deployment mounts, `.env`, Compose projects, and image version labels.
- Version detection remains fail-closed and avoids exposing configuration credentials.

### Upgrade

This release targets `linux/amd64` and adds no database migrations. Preserve your database, `config.yaml`, and encryption key. Use the version menu, or set `AIRMUX_VERSION=v0.1.5` in `.env` and run the Compose commands above. If `AIRMUX_APP_IMAGE` is pinned, replace it with the `image` value in the attached `release-manifest.json`.

Update and recreate the updater service as well to receive improved diagnostics. Keep `deployment.directory`, `AIRMUX_DEPLOY_DIR`, and the actual deployment directory consistent, with `config.yaml`, `compose.yaml`, and `.env` present.
