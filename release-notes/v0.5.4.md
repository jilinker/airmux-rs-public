# Airmux RS v0.5.4

本次调整系统更新交互与公共方案维护页面。

## 更新交互

- 点击“立即重启”直接执行已准备的任务，取消二次确认，保留执行前校验和重复提交保护。
- 本版界面跟踪到更新成功并核对目标版本就绪后自动刷新。短暂离线或仍返回旧版本时继续观察；历史成功记录不会循环刷新，失败和需要人工恢复时保留现场。
- 自动刷新由本版页面代码执行：已经打开的 0.5.3 页面首次升级至本版后，仍需手动刷新一次。加载本版页面后的后续更新会自动刷新。

## 公共方案

- 基本信息、方案地区和节点集中在“基本与节点”页签维护；分组、规则集、规则路由与 DNS 解析地址继续独立维护。
- 同页保存仍按基本信息、地区、节点顺序提交实际改动，保留成功步骤和其他页草稿；失败后只继续未完成的步骤。
- 新建公共方案的公共测速地址默认为 `https://www.g.cn/generate_204`，已有方案地址不自动覆盖。

## 安装与升级

- 镜像为 `docker.io/jaelinker/airmux:v0.5.4`，支持 `linux/amd64`，发行附件提供固定摘要。
- 最低可升级版本仍为 **0.5.0**，数据库代际为 `plan-local-v1`；旧 `0.4.x` 需要独立空库安装。
- 本版没有新增迁移，十二份已发布 SQL 保持原摘要，不批量回填或覆盖已有测速地址。
- 更新时保留原数据库、程序加密主密钥、SSH 主机记录和更新器状态；失败后按部署指南保留备份与现场，不删除迁移历史。

## 验证范围

Rust 工作区 108 项、隔离 PostgreSQL 数据库 38 项、前端 239 项和 Python 55 项回归通过，接口类型生成、类型检查、生产构建与原型构建通过。覆盖同页分步保存、失败续传、默认测速地址、更新结果不明时核对状态、版本未就绪时继续观察、成功后仅刷新一次，以及退出账号后的迟到请求处理。

正式候选镜像通过三文件空库安装，确认十二条迁移、七条默认地区、首次改密、静态页面、新方案默认测速地址、大规则按需读取与分区保存正常。正式 0.5.3 经真实更新器升级至本版，原方案完整状态、版本、规则密文及既有测速地址保持不变。

本版没有新增 SQL，故障演练通过隔离环境的迁移入口注入退出码 42，确认进入 `needs_recovery` 并停止 API。成功与失败流程的两份真实备份均恢复到独立库，十四张核心表完整数据指纹一致，两个恢复库均使用旧 0.5.3 镜像恢复就绪。

本机浏览器已使用合成接口检查合并页面、默认测速值、直接重启和成功后的整页刷新；不代表用户生产部署的实机更新验收。

Mihomo v1.19.33 的四个固定参考用例通过原生检查，无效配置按预期拒绝。Loon 按既有要求继续暂缓验证；未操作用户部署或业务数据库。
