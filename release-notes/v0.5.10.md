# Airmux RS v0.5.10

DNS 策略与 Fake IP 排序项显示当前规则集名称和配置来源；功能配置允许不设主组，同名手动主组直接复用。

## 排序摘要

- DNS 策略显示配置名称、解析用途和规则集名称或原生域名表达，不再展示内部 JSON 或规则集标识。
- 区分普通域名解析与节点服务器解析；Fake IP、路由排序同步显示所属配置，Loon Host 解析补充用途说明。
- 跨配置同名规则去重后读取实际采用对象的名称，规则集改名后同步显示最新名称。方案编辑与配置更新影响面板保持一致，原有排序身份与顺序保留。

## 功能主组

- 基础配置仍必须且只能维护一个手动主组。功能配置可不设主组，也可按需维护一个主组，适用于只补充 DNS、路由或独立入站的功能。
- 基础与功能配置中的同名手动主组在方案中复用同一组，成员和顺序只维护一次，不再因主组同名选择或跳过整个功能配置。各功能的规则、解析与节点仍参与组合。
- 方案记录共享组名称与身份，移除其中一个同名来源后继续保留成员和出口。地区测速组与手动主组具有不同职责，仍不可同名复用；DNS、规则与入站等实际内容冲突继续明确选择。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.10`，平台 `linux/amd64`。固定摘要与实际源码提交见发行附件。
- 无新增 SQL，沿用十三份不可变迁移和数据库代际 `plan-local-v1`。从 `0.5.9` 升级保留现有配置、组合方案及访问链接。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前的版本升级会执行 `0.5.9` 引入的清理迁移，删除旧公共方案、客户端方案、相关归档和全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料及系统配置保留。升级前备份数据库并保管原加密主密钥；旧 `0.4.x` 仍须独立空库安装。

## 验证范围

- Rust 工作区 125 项、前端 286 项、PostgreSQL 显式隔离库 35 项和 Python 55 项回归通过；格式、契约生成、类型检查、生产与原型构建通过。
- 最终镜像完成三文件空库安装、默认资料与首次强制改密验证。真实 HTTP 验证无主组功能、同名主组复用、改名拆分、排序名称、保存重读和入站生成；产物通过 Mihomo v1.19.33 原生检查。
- 从正式 `0.5.9` 完成正常升级、故障停机及两份独立备份恢复；26 张业务表指纹保持一致，恢复库由旧版镜像成功读取节点和方案并生成配置。
