Airmux RS v0.2.0 — 从代理组管理关联路由规则 / Manage routing rules from proxy groups

### 更新内容

- 方案模板的“分组设置”和配置方案的“代理组”列表新增路由操作按钮，并显示关联规则数量；没有关联规则的分组也可直接新增。
- 弹窗反向展示出站指向当前分组的规则，支持搜索、启用状态筛选、行内编辑、确认删除和新增。规则集按名称选择，引用仍使用 UUID。
- 保留完整路由表的优先级编号和现有顺序。新增规则默认指向当前分组，可插入完整路由表最前、当前组最后一条之后，或末尾 MATCH 之前。
- 默认组同时展示“跟随默认组”的规则；MATCH 固定末尾、只读，不计入可编辑规则数量。DNS 策略和经其他分组间接转发的规则不包含在此视图中。
- 修改先保留在弹窗草稿，点击“应用修改”后写入页面草稿。模板仍需“保存并生成版本”，配置方案沿用自动保存；发布后客户端才使用新规则。
- 应用时按规则 ID 合并，保留其他规则的最新修改和顺序。同一规则发生冲突或默认组角色发生变化时拒绝覆盖，并保留弹窗中的修改。
- 新增匹配内容、规则集引用、IP 网段和“不解析”兼容性校验；复用现有主题、弹窗、滑动开关和 Lucide 图标，支持窄屏、键盘和深色模式。

### 升级说明

镜像架构为 `linux/amd64`。本版本没有新增数据库迁移，已有 27 个迁移保持不变。保留数据库、`config.yaml` 和加密密钥，无需重新初始化管理员账号。

推荐通过系统版本菜单执行在线更新。手动升级时，将 `.env` 中的 `AIRMUX_VERSION` 改为 `v0.2.0`，然后执行：

```sh
docker compose pull api frontend updater
docker compose up -d --wait
docker compose ps
```

如果 `AIRMUX_APP_IMAGE` 已被在线更新设置为固定摘要，手动升级时需将其替换为本 Release 附件 `release-manifest.json` 中的 `image`。该覆盖值优先于 `AIRMUX_VERSION`。同时更新 api、frontend 和 updater。

### Changes

- Added a routing action and related-rule count to proxy-group rows in both plan templates and plans, including groups with no existing rules.
- The dialog lists rules whose outbound points to the current group. It supports search, enabled-state filtering, inline editing, confirmed deletion, and creation. Rule-set selection keeps UUID references.
- Existing global route priority and order are preserved. New rules target the current group and can be inserted first, after the group's last rule, or at the end before MATCH.
- Default groups also include rules that follow the default group. MATCH remains read-only at the end and is excluded from the editable count. DNS policies and indirect group references are outside this view.
- Changes stay in an isolated dialog draft until applied. Templates still require saving a new version; plans use existing autosave. Clients receive changes only after publishing a plan version.
- ID-based merging preserves unrelated concurrent changes and order. Conflicting edits or a changed default-group role are rejected without discarding the dialog draft.
- Added validation for matcher values, provider references, CIDR ranges, and no-resolve compatibility. The UI reuses existing theme tokens, dialogs, switches, and Lucide icons, with narrow-screen, keyboard, and dark-mode support.

### Upgrade

This release targets `linux/amd64` and adds no database migrations. All 27 existing migrations remain unchanged. Preserve your database, `config.yaml`, and encryption key; administrator reinitialization is unnecessary.

Use the version menu, or set `AIRMUX_VERSION=v0.2.0` in `.env` and run the Compose commands above. If `AIRMUX_APP_IMAGE` is pinned, replace it with the `image` value in the attached `release-manifest.json`. Update api, frontend, and updater together.
