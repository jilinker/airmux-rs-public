# Airmux RS v0.5.12

方案功能配置默认收起，生成配置将手动分组放在地区分组前面，地区组默认使用地区代码命名。

## 本次改动

- 方案功能配置列表默认收起，可展开和收起。标题展示已添加数量，收起时仍可添加配置；原有节点选择和未保存草稿保留。
- 生成时先输出手动选择组，再输出地区测速组，两类各自顺序保持。
- 地区组默认使用 `HK`、`JP` 等地区代码；拆分后使用 `HK · 普通` 和 `HK · 家宽`。显式自定义名称继续优先。
- 成员、路由、DNS、独立入站及兜底按稳定标识解析实际输出名，出口候选及组合名称冲突检查同步采用上述规则。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.12`，平台 `linux/amd64`。固定摘要和实际源码提交见发行附件。
- 无新增 SQL，沿用十三份不可变迁移和数据库代际 `plan-local-v1`。从 `0.5.9` 至 `0.5.11` 升级保留现有配置、方案及访问链接。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前的版本升级仍会执行 `0.5.9` 引入的清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料及系统配置保留。升级前备份数据库并保管原加密主密钥，旧 `0.4.x` 仍须独立空库安装。

## 验证范围

- Rust 工作区 126 项、PostgreSQL 显式随机隔离库 35 项、前端 292 项和 Python 55 项回归通过；格式、契约生成、类型检查、生产及原型构建通过。
- 正式页面验证默认折叠、展开收起、草稿保留和收起时添加配置，桌面与 640px 视口无横向溢出。
- 最终镜像空库安装及真实 HTTP 保存重读生成通过，验证手动组前置、地区代码和家宽命名，以及成员、路由、DNS 与独立入站引用。实际产物通过 Mihomo v1.19.33 原生配置检查。
- 从正式 0.5.11 完成正常升级及故障停机演练，33 张业务表和十三份迁移保持一致。两份备份分别恢复至独立库，原密钥和旧镜像就绪后，可读取 35 个节点及方案并生成配置。
- Loon 本轮继续暂缓原生与实机验证，未做真实代理流量验证。
