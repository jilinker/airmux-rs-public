Airmux RS v0.1.4 — 方案模板删除 / Plan template deletion

### 更新内容

- 方案模板列表新增删除图标和确认弹窗，支持删除自定义模板；系统默认模板受到保护。
- 删除采用归档方式：模板从列表和新建方案选项中移除，已创建的配置方案、发布版本及访问链接不受影响。
- 后端校验管理员权限、请求来源和模板版本，拒绝直接越权调用及过期版本删除。
- 修复窄屏下操作图标和弹窗关闭图标被隐藏的问题。
- 部署文档补充默认自带 PostgreSQL 和使用已有 PostgreSQL 的配置说明。

### 升级说明

镜像架构为 `linux/amd64`，本版本没有新增数据库迁移。保留现有数据库、`config.yaml` 和加密密钥，无需重新初始化管理员账号。

可通过系统版本菜单执行在线更新。手动升级时，将 `.env` 中的 `AIRMUX_VERSION` 改为 `v0.1.4`，然后执行：

```sh
docker compose pull
docker compose up -d --wait
docker compose ps
```

若 `AIRMUX_APP_IMAGE` 已由在线更新设置为固定摘要，手动升级还需将其改为本 Release 附件 `release-manifest.json` 中的 `image`，否则该覆盖值会优先于 `AIRMUX_VERSION`。镜像仓库仍可通过 `.env` 配置。

### Changes

- Added deletion controls and a confirmation dialog for custom plan templates. System default templates remain protected.
- Deleted templates are archived and removed from creation options. Existing plans, published versions, and access links remain intact.
- The API enforces administrator permissions, allowed origins, and template version checks.
- Fixed hidden action and dialog close icons on narrow screens.
- Documented both bundled PostgreSQL and external PostgreSQL deployment options.

### Upgrade

This release targets `linux/amd64` and adds no database migrations. Keep your existing database, `config.yaml`, and encryption key. Use the version menu to update, or set `AIRMUX_VERSION=v0.1.4` in `.env` and run the Compose commands above. If `AIRMUX_APP_IMAGE` is already pinned by the updater, replace it with the `image` value in this Release's `release-manifest.json`; it takes precedence over the version variable. No administrator reinitialization is needed.
