# Air.mux v0.5.18

系统更新进度覆盖完整流程，停服期间可继续观察，失败原因与最近五次记录持续保留。

## 本次改动

- 细分发行读取、清单与平台校验、镜像下载与解压、迁移 SHA-256 校验、等待手动重启、停服、备份与可读性检查、镜像切换、迁移、API 就绪及实际版本校验、前端启动等事件。重启前校验失败也会保留日志。
- 下载量使用 Docker 引擎的真实分层进度，高频信息原位更新；已缓存层和整镜像缓存命中单独说明，不把解压计入下载量，总量未知时不估算整体百分比。沿用已有 Docker 仓库凭据和凭据助手。
- 新增任务范围的同源只读观察通道，API 停止期间仍可读取备份、迁移及失败结果。连接断开与任务失败分别表达，失败收尾持续观察到 API 停止确认完成。
- 同一标签页刷新后可恢复只读进度，不恢复账号或管理操作。权限一天有效；退出和账号切换清理本地材料，迟到响应不会污染新会话。
- 现有弹窗保留最近五次更新记录，检查更新不覆盖历史。关键日志最多二百条，截断明确提示，高频进度不占用日志条数。
- 保留手动重启和人工恢复，不新增取消、自动重试、断点续传或自动回滚。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.18`，平台 `linux/amd64`，固定摘要和源码提交见发行附件。
- 无新增 SQL，沿用十四份不可变迁移。从 `0.5.17` 升级保留现有节点、配置、方案、访问链接及引导状态。
- **首次启用完整停服观察需要配套升级 API、前端和更新器。应用在线更新不会自动重建 updater。** 维护者应在没有活动或待恢复任务时，保留状态卷及备份，将 `.env` 的 `AIRMUX_UPDATER_IMAGE` 指向配套发行摘要并重建更新器和前端。旧更新器仍按原方式在 API 恢复后补读日志。详细步骤见部署指南。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前升级仍会执行 `0.5.9` 的清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料及系统配置保留。升级前备份数据库并保管原加密主密钥；旧 `0.4.x` 须独立空库安装。

- 前端 334 项、Python 65 项、Rust 136 项及隔离 PostgreSQL 38 项回归通过；格式、契约、类型检查、正式与原型构建通过。
- 浏览器检查桌面与 640px 窄视口，覆盖下载、人工恢复和深色只读视图，无横向溢出，底部操作可达。
- Docker JSON 分块流、下载超时、缓存、仓库凭据解析、只读权限隔离、过期、篡改、记录保留、失败收尾和刷新恢复由隔离测试覆盖。真实公开缓存镜像拉取与 Nginx 配置检查通过。
- 最终镜像三文件空库安装、默认七个地区、首次管理员改密、真实接口保存重读及生成通过；实际 HTTP 版本、源码、架构和十四份 SQL 摘要一致。
- 从正式 0.5.17 正常升级与迁移退出码 42 故障演练通过，33 张业务表完整字段摘要及十四份迁移保持；两份自动备份均以原密钥和旧镜像恢复至独立库，真实 HTTP 可读取 35 个节点及方案并生成配置。

- 空库、升级、两份恢复与配套启用环境的 14 份实际生成配置通过固定摘要 Mihomo v1.19.33 原生校验。Loon 原生与实机验证继续暂缓，未验证真实代理流量。
