# Air.mux v0.5.21

校验失败明确指出配置、规则或字段及修复步骤，并修复合法远程规则缺少检查样本时无法保存的问题。

## 本次改动

- 手动规则缺少正文在预检阶段定位到配置名、规则名及具体字段，不再只显示通用方案错误。正文语法错误保留行列信息。
- 合法远程规则可在没有检查样本时保存。名称、行为、格式、URL 和更新周期仍严格校验；变更地址且没有新样本时清除旧样本，非法变更保留原正文，名称说明修改继续保留未变正文密文。
- JSON 输入区分缺失字段、类型、选项、未知字段、重复字段、语法行列、内容类型及请求过大；校验摘要显示首个具体问题，全部明细保留，不回显输入值或认证材料。
- 细化配置、方案、节点、来源 URL 与请求头、规则导入、地区、SSH、SMTP、账号、分页及链接生成的诊断。已知数据库约束使用安全原因，公开下载仍不暴露私人配置详情。
- 通知将技术路径翻译成中文字段、条目序号及业务名称。配置保存失败进入对应分区，规则错误展开已有资料管理并聚焦对应编辑入口，保留全部草稿；主组、Mihomo 和 Loon 设置定位到各自实际字段或分区。

## 升级说明

- 镜像 `docker.io/jaelinker/airmux:v0.5.21`，平台 `linux/amd64`，固定摘要和源码提交见发行附件。
- 无新增 SQL，沿用十四份不可变迁移。从 `0.5.20` 升级保留节点、配置、方案、访问链接和引导状态。
- 最低升级版本为 `0.5.0`。**从 `0.5.9` 之前升级仍会执行清理迁移，删除旧公共方案、客户端方案、相关归档及全部访问链接，不迁移或兼容旧方案。** 账号、来源、节点、管理员基础资料与系统配置保留。升级前备份数据库并保管原加密主密钥；旧 `0.4.x` 须独立空库安装。
- 远程规则没有检查样本不等于所有客户端均可生成。Mihomo 使用原始远程 URL；Loon 仍按成功样本检查兼容性，缺失时明确阻止生成。
- 保留详细更新与停服只读观察能力。从更早版本首次启用时仍须按部署指南配套更新 API、前端和更新器；应用在线更新不会自行重建 updater。

## 验证范围

- Rust 工作区回归、四十二项隔离 PostgreSQL 集成回归及三百五十九项前端测试通过，格式、类型检查、正式与原型构建通过。
- 新增诊断测试覆盖严格 JSON 重复字段拒绝、语法行列、原始值不外泄、来源及 SMTP 多字段问题、分页筛选定位、中文通知、草稿保留及正确编辑入口聚焦。
- 隔离数据库验证手动正文预检定位、合法远程缺省样本、非法远程定义失败且旧密文不变、地址变更清除旧样本及真实方案生成。远程无样本生成产物通过 Mihomo Meta v1.19.33 原生检查。
- Loon 原生、实机和真实代理流量继续暂缓。生产网络端到端与外部 SMTP、SSH 实服未在本轮重验。

- 最终镜像通过三文件空库安装、默认七地区、首次管理员改密，以及 HTTP 版本与源码标签检查。真实接口再次验证手动正文定位、远程定义校验、旧样本清理、无样本原始 URL 生成与共享合并回归。
- 从正式 0.5.20 正常升级及迁移退出码 42 故障演练通过，33 张业务表完整字段摘要及迁移历史保持；两份自动备份均用原密钥恢复到独立库并实际读取和生成，十五份真实产物通过固定摘要的 Mihomo 原生检查。
- 最终镜像真实浏览器验证后端字段错误的中文提示、分区切换、首错聚焦和草稿保留。升级与故障期间，只读通道在 API 停止后仍可读取任务结果。
