# Airmux RS v0.5.7

同一 DNS 可按匹配组选择不同查询出口，同一规则集或域名可关联多个 DNS，全部匹配继续统一排序。

## 解析策略

- 第一步共享公共 DNS 地址与附加参数，各匹配组批量选择规则集或填写域名，并独立指定各解析器的查询出口。
- 相同启用状态的同一匹配合并为一个排序项，保存为一条含多个解析器的原生策略。保留各 DNS 的地址、出口与完整参数，完全相同设置去重；停用关联保持独立。
- 全局排序允许同组条目分散排列，重排带动该匹配全部关联并保留解析器顺序。应用后重开保留顺序和身份，取消不改变外层方案。
- DNS 配置和匹配组均可独立收缩，标题保留地址、数量和出口摘要。抽屉最大宽度调整为 900px，窄窗口表单自动单列。
- 明确区分访问目标域名策略与代理节点服务器域名策略，后者需配置节点服务器解析器才生效。查询出口控制 DNS 请求连接，网站流量仍按路由规则处理。
- 保存错误会按原条目身份展开并定位共享参数或匹配组出口，保留抽屉中尚未应用的编辑内容。

## 安装与升级

- 镜像 `docker.io/jaelinker/airmux:v0.5.7`，支持 `linux/amd64`。固定摘要与实际源码提交见发行清单。
- 最低可升级版本 **0.5.0**，数据库代际 `plan-local-v1`。沿用现有接口和存储模型，没有新增迁移，十二份已发布 SQL 保持不变。
- 升级保留原加密主密钥、数据库、SSH 主机记录及更新器状态；旧 `0.4.x` 仍需独立空库安装。
